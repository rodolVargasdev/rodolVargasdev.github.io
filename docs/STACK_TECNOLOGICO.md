# Technology stack

Site: static HTML, CSS and JavaScript served as committed files, no framework and no runtime third-party code other than the dependency below. Since the bilingual change the pages are generated by a build step (see Build and capture tooling); the generated files are committed, so publishing is still a plain copy of this directory.

## Dependencies

| Package | Version (exact) | License | Source | Where it lives |
|---|---|---|---|---|
| three | 0.186.1 | MIT | https://cdn.jsdelivr.net/npm/three@0.186.1/build/three.module.min.js and https://cdn.jsdelivr.net/npm/three@0.186.1/build/three.core.min.js (npm package `three`) | `assets/vendor/three.module.min.js`, `assets/vendor/three.core.js` |

Notes on the two files:

- `three.module.min.js` imports `./three.core.js`, so the core build is vendored next to it. The file `three.core.js` is the published `three.core.min.js` of the same release, saved under the name the module imports.
- SHA-256 at vendoring time (2026-09-30): `three.module.min.js` 3bc833fceb6577bd1a380388f832ae61cd6e2f78ad02b0bf0d5adf5a4a9334fe, `three.core.js` 3b346151f65ffdfca3e4c002bd58966b78c423087fb48a873f83200de1bffc48. Both files report `REVISION = "186"`.

### Why it entered

The landing page needs a depth effect in the hero (a slowly rotating network of points with pulsing nodes, parallax with pointer and scroll) that plain CSS cannot produce. three.js renders it in WebGL. The pinned human-in-the-loop scene and the case chapters do not use it: they are CSS `position: sticky` plus scroll progress computed in JavaScript.

### Discarded alternatives

- Plain CSS or Canvas 2D: less depth, no real perspective or cheap per-point transforms.
- GSAP: not needed. Scroll effects use IntersectionObserver, requestAnimationFrame and CSS, so it would only add a dependency.

### Vulnerability check

- Date: 2026-09-30.
- Method: OSV query, `POST https://api.osv.dev/v1/query` with package `three`, ecosystem `npm`, version `0.186.1`.
- Result: empty response (`{}`), no advisory applies to 0.186.1. The only advisory published for the package, GHSA-fq6p-x6j3-cmmq, was fixed in 0.125.0.
- Re-run the same query before changing the version. Because the file is vendored, the version cannot drift: nothing is fetched from a CDN at runtime, so a newer, unreviewed release can never load by itself.

## Build and capture tooling (dev time only)

Nothing in this section loads in the browser. The sources live in `proyecto-work/site-src/` and `proyecto-work/capturas/`, outside this published tree.

| Tool | Version (exact) | Role |
|---|---|---|
| Node | 22.23.2 | Build step (`site-src/build.mjs`), check, tests and smoke. Built-in modules only: no package manager and no `package.json`, so no third-party package enters through Node. |
| Python | 3.13.7 | Capture script (`capturas/capture.py`) |
| Pillow | 12.3.0 | PNG to webp conversion in the capture script only. Installed only in the project virtual environment `site-src/.venv` (ignored by git); the global Python is not used for it. |
| Google Chrome | stable, 155.0.8059.39 (read from the installed `chrome.exe` on 2026-10-11, same build recorded in `capturas/index.md`) | Headless capture (`capturas/capture.py`) and smoke checks |

Container: none. The site is static, published on GitHub Pages, and the build output is committed, so there is no service or image to run. The build is a script run on the developer machine.

### Pillow: why it enters, vulnerability check and discarded alternatives

- Why: it converts the Chrome screenshots to webp (full size and thumbnail). It is a capture-only tool dependency, never a runtime dependency of the site.
- Version: 12.3.0, the lowest version that fixes every advisory published for the 11.x line used before.
- Vulnerability check, date 2026-10-11, tool: OSV query (`POST https://api.osv.dev/v1/query`, package `pillow`, ecosystem `PyPI`; `pip-audit` is not installed and was not installed for this).
  - Pillow 11.3.0: 36 records, 18 of them GHSA (for example GHSA-4x4j-2g7c-83w6, GHSA-6r8x-57c9-28j4, GHSA-cfh3-3jmp-rvhc). Not acceptable.
  - Pillow 12.3.0: empty response (`{}`), no advisory applies.
- Discarded alternatives: keeping 11.3.0 (vulnerable); Playwright for screenshots and conversion (a heavier tool and a package manager, and Pillow would still be needed for webp).
- Re-run, date 2026-10-11, when `capturas/capture.py` was added (same OSV query, package `pillow`, ecosystem `PyPI`, version 12.3.0): empty response (`{}`), no advisory applies. The version stays at 12.3.0.
- `capturas/capture.py` imports only the Python standard library and Pillow; it adds no other dependency. Pillow is used for PNG decoding, LANCZOS resize and webp encoding (`method=6`, quality 85 measured on the 30 published files).
- Re-run the same query before changing the version.

## Other external resources

- Google Fonts (Inter and Source Serif 4), loaded from `fonts.googleapis.com` and `fonts.gstatic.com`. It is the only external resource the pages request at runtime. If it fails to load, the pages fall back to system fonts.
